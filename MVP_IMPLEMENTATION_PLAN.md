# План реализации MVP для тестового задания (OpenBrain)

## 1. Цель MVP
Собрать рабочий Full Stack MVP на базе текущего монорепо `open-brain-test` с:
- backend на NestJS (ориентир по структуре: `impact-core-api`),
- frontend на React + Vite с UI через shadcn/ui (ориентир по подходу: `impact-client`),
- запуском через Docker.

## 2. Ограничения текущей итерации (не делаем)
В рамках MVP не реализуем:
- роли и ролевую модель доступа,
- логирование как отдельную подсистему,
- AI summary для описания заявки,
- интеграцию с mock API.

## 3. Архитектурный ориентир
- Backend: модульный NestJS-подход, DTO/валидация, TypeORM + миграции, структура модулей по фичам.
- Frontend: feature-oriented структура, UI-компоненты через shadcn/ui, работа с API через отдельный слой (services/api client).
- Контракты API: явные DTO и предсказуемые response-модели, чтобы фронт и бэк были слабо связаны.

## 4. Последовательный план работ

### Этап 1. Уточнение функционального скоупа
1. Зафиксировать минимальные пользовательские сценарии MVP (например: создание/просмотр/обновление заявок).
2. Зафиксировать сущности и их обязательные поля.
3. Описать acceptance criteria для каждого сценария.

### Этап 2. Проектирование backend API
1. Определить модули в backend (например: `applications`, `health`).
2. Описать REST-контракты:
   - `POST /applications`,
   - `GET /applications`,
   - `GET /applications/:id`,
   - `PATCH /applications/:id`.
3. Подготовить DTO и валидацию (`class-validator`, `class-transformer`).

### Этап 3. Слой данных и БД
1. Спроектировать таблицы и связи для MVP сущностей.
2. Создать миграции в стиле существующего backend.
3. Подготовить минимальные seed-данные для локальной проверки.

### Этап 4. Реализация backend
1. Создать модуль(и), сервисы, контроллеры, репозитории/DAO.
2. Реализовать бизнес-правила MVP без ролей и без AI summary.
3. Добавить базовые unit/e2e тесты на критичные сценарии.

### Этап 5. Подготовка frontend базы
1. Настроить структуру `frontend/src` под фичи и общий UI слой.
2. Установить и инициализировать shadcn/ui.
3. Добавить базовые UI-компоненты для MVP:
   - `Button`, `Input`, `Textarea`, `Select`,
   - `Form`, `Card`, `Table`, `Dialog`, `Toast`.

### Этап 6. Реализация экранов frontend
1. Экран списка заявок.
2. Экран создания заявки.
3. Экран просмотра/редактирования заявки.
4. Подключение к backend API через единый клиент (без mock API).

### Этап 7. Интеграция frontend + backend
1. Настроить переменные окружения (`VITE_API_URL`, backend env).
2. Проверить CORS и корректные HTTP-коды/ошибки.
3. Пройти smoke-тест основных пользовательских сценариев.

### Этап 8. Docker и локальный запуск
1. Создать `Dockerfile` для backend.
2. Создать `Dockerfile` для frontend.
3. Создать корневой `docker-compose.yml` для запуска:
   - backend,
   - frontend,
   - postgres.
4. Добавить init-команды (миграции/seed) в процесс старта backend контейнера.

### Этап 9. Финализация
1. Обновить README с командами запуска локально и через Docker.
2. Зафиксировать известные ограничения MVP.
3. Подготовить краткий чек-лист демонстрации.

## 5. Результат после выполнения плана
На выходе должен быть рабочий MVP с:
- backend API на NestJS,
- frontend интерфейсом на React + shadcn/ui,
- единым запуском через Docker Compose,
- без ролей, логирования, AI summary и mock API-интеграций.
